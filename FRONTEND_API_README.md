# Learnfy Backend API – Frontend Integration Guide

This document is the frontend-facing contract for the current Learnfy backend.

Base URL examples:

```text
http://localhost:3000
```

All JSON requests should use:

```http
Content-Type: application/json
```

Authentication is **session-cookie based** (Passport + express-session), not JWT.
The browser/frontend must send credentials on authenticated requests.

Fetch example:

```js
fetch("http://localhost:3000/api/courses", {
  credentials: "include"
});
```

Axios example:

```js
axios.get("http://localhost:3000/api/courses", {
  withCredentials: true
});
```

The frontend must never send or store the session cookie manually. The browser manages the `connect.sid` cookie.

---

## 1. Roles

| Role | Meaning |
|---|---|
| `student` | Can browse published courses, enroll, and access enrolled lesson content. |
| `teacher` | Can create/manage their own courses and lessons. |
| `admin` | Can manage student/teacher roles. Admin creation is done by the backend CLI, not the public API. |

New public registrations always create a `student` account. Only an admin can promote/demote a non-admin user through the role endpoint.

## 2. Authentication

### Register

```http
POST /api/user/auth/register
```

Body:

```json
{
  "username": "student02",
  "email": "student02@example.com",
  "password": "StrongPassword123!",
  "phone": "01012345672"
}
```

Success: `201`

Response:

```json
{
  "success": true,
  "message": "User has been created successfully",
  "data": {
    "id": "...",
    "username": "student02",
    "email": "student02@example.com",
    "phone": "01012345672",
    "role": "student"
  }
}
```

Do not send `role` from the frontend during registration.

### Login

```http
POST /api/user/auth/login
```

Body:

```json
{
  "username": "student02",
  "password": "StrongPassword123!"
}
```

Success: `200`. A session cookie is created.

### Logout

```http
POST /api/user/auth/logout
```

Requires authentication. Success: `204`.

### Get current user

```http
GET /api/user/:id
```

Requires authentication and the `:id` must belong to the current session user.

Example:

```http
GET /api/user/6a9b4eb36699e9ccacd70510
```

Success: `200`.

### Update current user

```http
PATCH /api/user
```

Requires authentication.

Allowed fields only:

```json
{
  "username": "new_username",
  "email": "new@example.com",
  "phone": "01012345679"
}
```

At least one field is required.
Password and role cannot be changed through this endpoint.

Success: `200`.

### Delete current user

```http
DELETE /api/user
```

Requires authentication. Success: `204` and the session is destroyed.

## 3. Public / Catalog Courses

### List courses

```http
GET /api/courses
```

No authentication is required.

Behavior:

- Anonymous/student/admin requests return **published** courses.
- A teacher request returns **that teacher's courses**, including drafts.

Example:

```js
fetch(`${API_URL}/api/courses`, { credentials: "include" });
```

Success: `200`.

### Get one course

```http
GET /api/courses/:courseId
```

Requires authentication.

Behavior:

- Teacher can read their own draft/published course.
- Other authenticated users can read published courses only.

Success: `200`.

## 4. Teacher Dashboard Courses

### My courses

```http
GET /api/teacher/courses
```

Requires:

```text
Authenticated teacher
```

Returns only courses owned by the current teacher.

Success: `200`.

### Create course

```http
POST /api/courses
```

Requires authenticated `teacher`.

Body:

```json
{
  "title": "Advanced Express.js",
  "description": "Build secure and scalable APIs with Express.js.",
  "category": "Programming",
  "price": 200,
  "thumbnail": "https://example.com/image.jpg",
  "level": "beginner",
  "status": "draft"
}
```

Required fields:

```text
title
description
category
price
```

Allowed `level` values:

```text
beginner
intermediate
advanced
```

Allowed `status` values:

```text
draft
published
```

The `teacher` field is generated by the backend from the authenticated user. Do not send it from the frontend.

Success: `201`.

### Update course

```http
PATCH /api/courses/:courseId
```

Requires authenticated teacher who owns the course.

Body can contain any subset of:

```json
{
  "title": "Updated title",
  "description": "Updated description",
  "category": "Programming",
  "price": 150,
  "thumbnail": "https://example.com/image.jpg",
  "level": "intermediate",
  "status": "published"
}
```

Success: `200`.

### Delete course

```http
DELETE /api/courses/:courseId
```

Requires authenticated teacher who owns the course.

A course cannot be deleted after enrollment or payment records exist. In that case the API returns `409`.

Success: `204`.

## 5. Teacher / Student Lesson APIs

### List course lessons

```http
GET /api/courses/:courseId/lessons
```

Requires authentication.

Behavior:

- Course owner teacher: receives all lessons.
- Enrolled student: receives all lessons.
- Non-enrolled student: receives preview lessons only (`isPreview: true`).
- Draft courses are not exposed to non-owner users.

Success: `200`.

### Get one lesson

```http
GET /api/courses/:courseId/lessons/:lessonId
```

Requires authentication.

- Course owner teacher: full access.
- Enrolled student: full access.
- Non-enrolled student: only preview lesson access.
- Draft course content is not exposed to non-owner users.

Success: `200`.

### Create lesson

```http
POST /api/courses/:courseId/lessons
```

Requires authenticated teacher who owns the course.

**Content-Type:** `multipart/form-data`

Required text fields:

```text
title
description
duration
order
```

Optional:

```text
isPreview
```

Exactly one video source is required:

```text
youtubeUrl
```

OR:

```text
video = <video file>
```

Example multipart fields:

```text
title       = Introduction to Node.js
description = Learn the basics of Node.js
duration    = 600
order       = 1
isPreview   = false
youtubeUrl  = https://www.youtube.com/watch?v=TlB_eWDSMt4
```

Do not send both `youtubeUrl` and `video`.

Supported upload extensions include `.mp4`, `.webm`, `.mov`, `.mkv`, `.avi`, `.mpeg`, `.mpg`.
The configured upload size limit is controlled by `MAX_VIDEO_UPLOAD_BYTES` (default in `.env.example`: 50 MB).

Success: `201`.

### Update lesson

```http
PATCH /api/courses/:courseId/lessons/:lessonId
```

Requires authenticated teacher who owns the course.

**Content-Type:** `application/json`

Allowed fields:

```json
{
  "title": "Updated lesson title",
  "description": "Updated lesson description",
  "duration": 900,
  "order": 1,
  "isPreview": false
}
```

Success: `200`.

### Delete lesson

```http
DELETE /api/courses/:courseId/lessons/:lessonId
```

Requires authenticated teacher who owns the course.

Success: `204`.

## 6. Student Dashboard / Enrollment

### My enrolled courses

```http
GET /api/student/courses
```

Requires authenticated `student`.

Returns only enrollments belonging to the current student.

Example response:

```json
{
  "success": true,
  "data": [
    {
      "enrollmentId": "...",
      "enrolledAt": "2026-09-04T23:21:24.545Z",
      "payment": null,
      "course": {
        "_id": "...",
        "title": "Node.js Backend",
        "description": "Learn Node.js and Express.",
        "teacher": "...",
        "category": "Programming",
        "price": 0,
        "thumbnail": null,
        "level": "beginner",
        "status": "published",
        "rating": 0
      }
    }
  ]
}
```

### Enroll / Create payment

```http
POST /api/payments/create
```

Requires authenticated `student`.

Body:

```json
{
  "courseId": "6a9b49e7e6fdf8bc83a90ab0"
}
```

Do **not** send `amount`. The backend always reads the price from the course record.

For a free published course (`price = 0`), the endpoint creates the enrollment directly and does not call Fawry.

For a paid course, the endpoint creates a pending payment and starts the Fawry flow.

Success for free enrollment: `201`.

Duplicate enrollment: `409`.

Paid-course Fawry configuration missing: `503`.

## 7. Payment Status

### Get my payment status

```http
GET /api/payments/:paymentId
```

Requires authentication.

Only the authenticated user's own payment can be returned.

Success: `200`.

Example response:

```json
{
  "success": true,
  "data": {
    "paymentId": "...",
    "courseId": "...",
    "amount": 300,
    "currency": "EGP",
    "status": "pending",
    "referenceNumber": "...",
    "paidAt": null
  }
}
```

Frontend status values currently include:

```text
pending
paid
failed
refunded
```

## 8. Fawry Webhook

```http
POST /api/payments/fawry/webhook
```

This endpoint is for **Fawry server-to-server callbacks**, not for the frontend browser.

Required fields:

```json
{
  "fawryRefNumber": "...",
  "merchantRefNum": "507f1f77bcf86cd799439011",
  "paymentAmount": "300.00",
  "orderAmount": "300.00",
  "orderStatus": "PAID",
  "paymentMethod": "PayAtFawry",
  "messageSignature": "64-character-sha256-hex"
}
```

Optional:

```text
paymentReferenceNumber
```

Accepted order statuses:

```text
PAID
EXPIRED
CANCELED
CANCELLED
```

The backend validates the signature, payment method, and amount before updating the payment. A valid `PAID` callback also creates the enrollment idempotently.

Do not call this endpoint from the frontend.

## 9. Admin APIs

### Change user role

```http
PATCH /api/admin/users/:id/role
```

Requires authenticated `admin`.

Body:

```json
{
  "role": "teacher"
}
```

Allowed target roles:

```text
student
teacher
```

`admin` is intentionally not allowed through the HTTP role-management endpoint.
Admin accounts are bootstrapped with the CLI.

Success: `200`.

Non-admin caller: `403`.

### Create / ensure the admin account

This is a backend CLI operation, not a frontend endpoint:

```bash
npm run create-admin
```

Environment variables:

```env
ADMIN_USERNAME=admin
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=change-me
ADMIN_PHONE=01000000000
ADMIN_RESET_PASSWORD=false
```

## 11. Common HTTP errors

All errors use the general shape:

```json
{
  "success": false,
  "message": "..."
}
```

Validation errors may include:

```json
{
  "success": false,
  "message": "Validation failed",
  "errors": [
    {
      "field": "price",
      "message": "Must be a number between 0 and 100000000"
    }
  ]
}
```

Important statuses:

| Status | Meaning |
|---:|---|
| `400` | Invalid body, parameter, query, JSON, or upload. |
| `401` | Login/session required. |
| `403` | Authenticated but not allowed. |
| `404` | Resource/route not found. |
| `409` | Duplicate/conflicting resource (for example duplicate enrollment). |
| `413` | Uploaded file is too large. |
| `429` | Rate limit exceeded. |
| `503` | Dependency/configuration unavailable (for example Fawry not configured). |
| `500` | Unexpected server error. |

## 12. Rate limits

Limits are currently per IP address and are configured in `.env`:

| Area | Default |
|---|---:|
| All API routes | 120 requests / minute |
| Login | 10 requests / 15 minutes |
| Registration | 5 requests / hour |
| Payment creation | 5 requests / minute |
| Fawry webhook | 30 requests / minute |
| Admin role endpoint | 60 requests / minute |

When `429` is returned, the response includes a `Retry-After` header.

The current limiter is in-memory and therefore intended for a single backend process. If the backend is horizontally scaled, replace the limiter store with a shared store such as Redis before relying on rate limits cluster-wide.

## 13. CORS / Frontend setup

The backend reads:

```env
CORS_ORIGIN=http://localhost:5173
```

Multiple origins can be comma-separated.

For browser requests using the session cookie, frontend requests must include credentials:

```js
fetch(`${API_URL}/api/user/auth/login`, {
  method: "POST",
  credentials: "include",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ username, password })
});
```

For authenticated API calls, continue to use `credentials: "include"`.

Production normally requires:

```env
NODE_ENV=production
CORS_ORIGIN=https://your-frontend.example.com
TRUST_PROXY=true
```

and HTTPS so the secure session cookie can be used safely.

## 14. Frontend flow examples

### Student flow

```text
Register
  ↓
Login
  ↓
GET /api/courses
  ↓
GET /api/courses/:courseId
  ↓
POST /api/payments/create
  ↓
Free course → enrolled immediately
Paid course → wait for Fawry payment
  ↓
GET /api/payments/:paymentId
  ↓
GET /api/student/courses
  ↓
GET /api/courses/:courseId/lessons/:lessonId
```

### Teacher flow

```text
Login
  ↓
GET /api/teacher/courses
  ↓
POST /api/courses
  ↓
PATCH /api/courses/:courseId
  ↓
POST /api/courses/:courseId/lessons
  ↓
PATCH /api/courses/:courseId/lessons/:lessonId
  ↓
DELETE /api/courses/:courseId/lessons/:lessonId
```

### Admin flow

```text
Login
  ↓
PATCH /api/admin/users/:id/role
  ↓
role = student | teacher
```

## 15. Frontend contract rules

1. Never send `teacher`, `student`, `payment`, or other ownership fields to try to override backend authorization.
2. Never trust a frontend role check as a security control; the backend is authoritative.
3. Do not call the Fawry webhook from the browser.
4. Do not send a payment amount from the frontend; send only `courseId`.
5. Use `credentials: "include"` for login/logout/authenticated API calls.
6. For lesson creation, use `multipart/form-data`; for lesson update, use JSON.
7. Do not send `role` during public registration.
